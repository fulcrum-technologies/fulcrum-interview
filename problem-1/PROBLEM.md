# 과제 안내

[실행 안내](README.md)를 따라 프로젝트를 먼저 실행해 보세요. 이 문제는 기존 Next.js 대시보드의 코드를 읽고 개선하는 코딩 과제입니다.

- 면접 중 **20분 내외**로 진행합니다. 모든 개선을 완성하기보다 중요한 문제부터 다루세요.
- **AI 채팅, 코드 생성, AI 자동완성은 사용할 수 없습니다.** 일반 IDE 기능과 공식 문서는 사용할 수 있습니다.
- 완성도보다 **판단의 근거**를 봅니다. 무엇을 왜 그렇게 고쳤는지가 코드만큼 중요합니다.
- 수정 전에 발견한 문제와 우선순위를 짧게 설명하고, 수정 후 확인한 내용을 공유해 주세요.

---

## 문제 1 — 코드 리뷰와 수정

방금 머지된 대시보드 기능(`/login`, `/dashboard`)에 대해 아래와 같은 제보가 들어왔습니다.

> 1. "대시보드 첫 로딩이 체감상 너무 느립니다. 데이터가 몇 개 없는데도요."
> 2. 보안팀: "브라우저에서 대시보드 응답을 열어보면 서버에만 있어야 할 값이 보입니다."
> 3. CS팀: "일반 사용자가 **다른 사람의 글**을 삭제했고, 권한이 없어야 할 발행/발행취소도 수행했다는 인입이 있습니다."

### 적용할 권한 정책

- 로그인한 사용자는 대시보드의 전체 글을 볼 수 있습니다.
- 일반 사용자는 **본인 글만 삭제**할 수 있습니다.
- 관리자는 모든 글을 삭제할 수 있습니다.
- 발행/발행취소는 **관리자만** 할 수 있습니다.
- 로그인하지 않은 사용자는 삭제·발행/발행취소를 할 수 없습니다.

### 해야 할 일

1. 세 제보의 **원인을 코드에서 찾아** 설명하세요.
2. 각각을 **근본적으로 수정**하세요. 증상만 가리는 수정(예: UI 에서 버튼 숨기기)은 정답으로 보지 않습니다.
3. 같은 유형의 문제가 재발하지 않도록 하려면 팀 차원에서 무엇을 하겠는지 간단히 적어주세요 (린트 규칙, 구조, 리뷰 체크리스트 등 자유).

### 범위

- `/dashboard`와 관련 조회 함수·Server Action을 중심으로 진행하세요. `/`의 Posts 데모는 별도 예제입니다.
- 통계와 팀원 조회의 지연은 외부 서비스 응답 시간을 재현한 것입니다. 지연을 삭제하거나 줄여서 해결하지 마세요.
- 데모 계정을 선택하는 로그인 방식은 과제용입니다. 로그인 시스템 전체를 새로 만들 필요는 없습니다. 로그인한 사용자의 역할·글 소유권을 서버에서 검증하는 부분은 과제에 포함됩니다.
- `.env.example`의 분석 키는 노출 문제를 재현하기 위한 **가짜 값**이며, 외부 API 호출이나 유료 서비스 연결은 필요하지 않습니다.
